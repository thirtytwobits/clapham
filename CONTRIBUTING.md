# Contributing

Read [AGENTS.md](AGENTS.md) before changing the repository. Cargo selects the gate
compiler from `rust-toolchain.toml`.

[The release contract](docs/contract.md) links each guarantee to named tests. Update the
guarantee and its test together when behaviour changes. Start with
[composing an application](docs/composing.md) for the worked example. Each crate's README is
included as its crate-level API documentation; its Rust examples run as doctests. Public
items require documentation, and the gate builds API docs with warnings denied.

```console
cargo xtask check
cargo xtask boundaries
cargo xtask docs
cargo xtask api
cargo xtask schemas --check
cargo xtask release-check
```

`check` runs dependency, crate-file and generated-schema checks, formatting, Clippy with
warnings denied, tests and documentation with warnings denied, for default features and
all features. It also validates release metadata, the changelog and Cargo package inventories.
Its documentation check (`cargo xtask docs`) resolves each contract Evidence paragraph's
backticked function names against the preceding linked Rust file, requires evidence for
each guarantee, and compares the composing guide's first Rust block with the core README's
Quickstart. The README doctest compiles that shared example. These checks catch reference
and example drift; reviewers still judge whether the tests prove the documented guarantees.
Inventories follow Cargo's file selection, including non-ignored untracked files under a
crate: an unexpected local file can therefore fail `check`. Source archives are supported;
only Cargo's generated `.cargo_vcs_info.json` may be absent outside a Git work tree.
Tests and support fixtures are shipped so tagged consumers can reproduce conformance checks.
`boundaries` checks each declared dependency, including aliases, development and build
dependencies, optional dependencies and dependencies for other targets. No command needs
Node or another build system.

Install the API tools once:

```console
rustup toolchain install nightly-2025-08-02 --profile minimal
cargo +1.99.0 install cargo-public-api --version 0.50.2 --locked
```

`api/toolchain.json` records the API tool versions. `cargo xtask api` refuses missing or
stale snapshots and an unexpected cargo-public-api version. Accept an intentional API
change with `cargo xtask api --update`, review the resulting `api/*.txt` diff and commit it.
The command runs from any directory in the workspace and normalises line endings.

Check the minimum supported Rust versions with the committed lockfile:

```console
cargo +1.85.0 check --locked -p clapham -p clapham-cli
cargo +1.85.0 test --locked -p clapham -p clapham-cli
cargo +1.85.0 test --locked -p clapham --features serde_json/preserve_order revision_
cargo +1.88.0 test --locked -p clapham-mcp-server -p clapham-mcp-client -p clapham-conformance -p clapham-lists --all-features
cargo +1.88.0 check --locked -p clapham-mcp-server -p clapham-mcp-client --no-default-features
cargo +1.88.0 check --locked -p clapham-mcp-server -p clapham-mcp-client --no-default-features --features stdio
cargo +1.88.0 check --locked -p clapham-mcp-server -p clapham-mcp-client --no-default-features --features http
```

Generate the public operation, refusal and catalogue schemas and the CLI output envelope
with `cargo xtask schemas`. Review and commit changes to `crates/*/schemas/*.json`;
`cargo xtask schemas --check` checks them without writing. The schemas use JSON Schema
2020-12. Tests validate descriptors and refusals against the checked-in files.

The MCP crates reserve `stdio` and `http` features for their transports. The neutral
conformance contribution and CLI are implemented, including process output and safeguards.
The reusable conformance harness and the lists executable cover the CLI, both MCP servers
and the client bound to both servers. The Rust 1.88 lane includes this complete process matrix.

See [the workspace guide](docs/README.md) for the crate boundaries and CI lanes.

The MCP wire-form record is generated by its conformance test. Ordinary checks refuse a
changed surface. After reviewing an intended change, run
`CLAPHAM_WRITE_RECORDS=1 cargo test -p clapham-conformance --test mcp_protocol` and include
`crates/clapham-conformance/records/mcp-protocol.json` in the change.

`cargo xtask check` clears `CLAPHAM_WRITE_RECORDS` for child Cargo commands and compares the
wire record's canonical bytes. An inherited writing flag cannot silently update a stale record.

Use `cargo xtask release-check <tag> --notes <path>` to validate a proposed release tag and
extract its changelog section. Update `release.json` when a crate intentionally adds or
removes a shipped file. See [RELEASING.md](RELEASING.md) for versioning, drafts and the
temporary RC smoke check, and [SECURITY.md](SECURITY.md) for private reporting.
