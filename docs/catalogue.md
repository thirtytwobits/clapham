# Catalogue and version

Every composed set contains two workspace queries under the reserved `clapham`
namespace. The application cannot contribute under that namespace. Built-ins use
the normal input and output validation, gate, selection and cancellation policies,
and consume the same operation, catalogue and schema budgets as other operations.

## Describe

Calling `clapham.describe` with `{}` returns an array of complete descriptors in
name order, including their input and output schemas. Only operations in the
caller's selection for which the gate returns `Allow` appear. `Deny` and `Pending`
both hide a candidate. The gate runs anew for each candidate on every request; the
catalogue does not cache admission decisions or dispatch the operations it lists.

Calling with `{"name": "lists.get"}` returns that one descriptor as a JSON object.
An unknown, unselected, denied or pending name returns the same `unknown_operation`
refusal, categorised as `not_found`. No schema or admission details leak in that
refusal. A named lookup asks the gate only about its selected target. The outer
call still asks the gate about `clapham.describe` first; the gate can deny or defer
discovery itself with `not_admitted` or `admission_pending`.

The optional `name` must be a string. Null, other types and extra input fields
refuse as `invalid_input`. The public `Catalogue` type represents an array as
`Catalogue::Operations` and a named result as `Catalogue::Operation`. Both forms
validate against [catalogue.schema.json](../crates/clapham/schemas/catalogue.schema.json),
generated by `cargo xtask schemas` and checked by `cargo xtask schemas --check`.

A selection must explicitly contain `clapham.describe` to call it; `set.all()`
includes it. Introspection is not added automatically to a narrower selection.
Clones of a set retain its selection identity, so they can use the same selections.

`ComposedOperation::invoke` is the low-level primitive and has no selection policy.
Invoking `clapham.describe` that way considers the full catalogue, still filtering
each descriptor through the gate for the principal. Use `ComposedSet::call` for
caller-facing discovery so the selection and outer admission checks also apply.
The internal catalogue shares immutable descriptors and does not retain handlers,
avoiding ownership cycles through the built-in operation.

## Version

`clapham.version` accepts `{}` and returns `VersionInfo`, for example:

```json
{
  "clapham": "0.1.0",
  "application": { "name": "lists", "version": "1.2.3" }
}
```

The `clapham` field is the core library's package version. Supply the application
identity at composition:

```rust
let options = clapham::ComposeOptions {
    application: Some(clapham::ApplicationInfo {
        name: "lists".into(),
        version: "1.2.3".into(),
    }),
    ..Default::default()
};
let set = clapham::compose_with_options([], clapham::Bounds::default(), options)?;
```

The name and version are opaque strings retained without rewriting. With default
options no application identity is recorded, and the `application` field is omitted.
The identity is fixed for the set and its clones. It is result metadata, so changing
it does not change a descriptor or selection revision. The gate and the caller's
selection govern access to this operation too.
